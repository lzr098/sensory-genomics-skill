## 🐛 Bug 修复记录

### 根本原因

`SensoryPipeline._merge_vep()` 函数（`scripts/src/main.py:190`）使用了：
```python
tc = consequences[0]  # ← 始终取 NLRP3 转录本
```

NLRP3 与 OR2B11 基因区域重叠约 550bp（NLRP3: chr1:247,332,331–247,449,668, +链；OR2B11: chr1:247,449,118–247,458,105, −链）。VEP 按染色体顺序返回转录本，NLRP3（+链）排在最前面，因此 `consequences[0]` 始终是 NLRP3 的下游基因变异 (downstream_gene_variant)，而非 OR2B11 的编码区后果。

### 修复方案

实现 `_score_transcript()` / `_select_best_transcript()` 方法，对每个转录本打分：
- canonical 转录本：+10
- protein_coding 生物型：+5
- 后果严重度排名：+0–40（frameshift=36 > missense=30 > UTR=18 > downstream=11）

选择得分最高的转录本作为变异后果代表，而非盲目取第 0 个。

### 验证

对 chr1:247,451,959 (GA>G) 的 VEP 响应中有 19 个 transcript_consequences：
- NLRP3 典型转录本 → downstream_gene_variant（排名 11）
- OR2B11 典型转录本 → frameshift_variant（排名 36）
- 修复后正确选择得分更高的 OR2B11 转录本 ✔️
